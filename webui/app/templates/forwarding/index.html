How queries are answered

  1. A zone this server is authoritative for is answered from its own data, by forwarding to the authoritative server {% if local_target %} at {{ local_target }} {% endif %}. Those rules are marked local zone above and are kept in step automatically — creating or deleting a zone updates them.
  2. Otherwise the most specific matching forward zone above wins.
  3. Otherwise the global forwarders.
  4. With no global forwarders, the resolver walks down from the root servers itself.

A forwarded zone is answered from outside the public DNS chain, so it cannot be DNSSEC-validated against it. This resolver therefore serves DNSSEC records but does not validate; a validating client downstream still can.
